海岸工程团队需要一套后端来处理线性重力波的色散反演：给定一批海况（每条含水深、波高、周期），先按线性波理论把波数解出来，再导出波长、相速度、群速度、相对水深分区，并能在指定的水平位置与时刻还原波面高程。它跑在服务器上、通过 HTTP 对外，不做潮汐预报、不写观浪日志、不接海事订舱，也没有账户体系。

色散求解是全部计算的地基。角频率取二π除以周期。重力加速度在整套服务里钉死为 9.80665 米每二次方秒，任何模块都不许再引入第二个本地常数。波数要让角频率的平方等于重力加速度、波数、以及波数与水深之积的双曲正切三者相乘；这是个隐式方程，须用迭代在钉死容差内求根，若无法闭合就当作错误拒绝。水深、波高、周期三者都必须为正。相对水深以波数乘水深来划：大于 π 记为深水，小于 π 的十分之一记为浅水，落在两者之间的必须老老实实走完整双曲正切，严禁在中等水深偷换成深水闭式。作为自检基准，深水极限下相速度应回到重力加速度乘周期除以二π、波长回到重力加速度乘周期平方除以二π，浅水极限下相速度应回到重力加速度乘水深再开方。波高与水深之比一旦越过服务钉死的线性适用上限，直接拒绝而不是硬输出一套线性结果，这个上限要能从配置回显里读到。

运动学量必须与色散解出的那个波数共用同一个数，不允许色散解一套、相速度和群速度再另解一套。相速度是角频率除以波数。群速度等于相速度的一半乘以一个括号因子，该因子为 1 加上二倍波数水深再除以二倍波数水深的双曲正弦；深水时因子趋于 1、群速度趋于相速度一半，浅水时因子趋于 2、群速度趋于相速度。波面高程取波高的一半乘以（波数乘水平位置减去角频率乘时间）的余弦，整套服务的相位约定必须前后统一。把双曲正切误写成普通正切，或把群速度一律当成相速度的一半而丢掉双曲正弦修正，都算实现错误。

以下判据必须成立，用来卡实现对不对：深水工况下单独把周期翻倍，波长约变四倍、相速度翻倍；把水深一路加深到进入深水区后，相速度不再随水深上涨；浅水工况下单独把水深变四倍，相速度变两倍；单独把波高翻倍，波数与相速度、群速度都不变，只有波面高程按同比例放大。服务须自带一个中等水深涌浪的示范算例，它的相对水深既明显小于深水判据、又明显大于浅水判据，必须走完整色散，且相速度严格落在深水闭式与浅水闭式之间。

对外接口围绕「解一条海况」和「批量解一组海况」两类请求组织：单条请求返回色散解与全部导出量；波面高程支持按位置、时间的网格一次性还原成二维数组。批量请求里若某一条参数非法（缺字段、非数值、非有限值、水深或波高或周期非正、色散无法在容差内闭合、波陡越过线性上限），要在返回里点明是第几条、哪个参数出的问题，并让其余各条照常算完返回，不能一条坏掉就整批失败或直接崩溃。每次核算连同输入与结果落库，供事后按条件检索历史。另需一个配置回显接口，把重力加速度、深浅水判据、线性适用上限与求根容差都读出来；再暴露一个供监控采集的运行状态端点。多请求并发时结果不得相互串扰、历史记录不得错乱。

用 Python 3.12 加 FastAPI 落地，持久化选 PostgreSQL 16，整套用 Docker Compose 一条命令构建并拉起服务与数据库。工程上把色散求根、相速度与群速度、波面高程还原、输入校验与持久化各自分到独立模块，不要挤在一个文件里。随附自动化测试，覆盖：深水相速度等于重力加速度乘周期除以二π、浅水相速度等于重力加速度乘水深再开方、中等水深走完整色散且相速度介于两极限之间、周期翻倍则深水波长约四倍且相速度翻倍、浅水水深四倍则相速度两倍、波高翻倍只放大高程不改波数、波陡越限被拒、非法参数被拒、批量部分失败其余成功、历史落库正确，以及并发多请求互不串扰。
